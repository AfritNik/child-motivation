# Развёртывание MVP в Yandex Cloud

## Согласованная схема

- одна небольшая виртуальная машина: приложение и PostgreSQL в контейнерах;
- постоянный публичный IPv4-адрес;
- Nginx принимает запросы из интернета и передаёт их приложению;
- бесплатный HTTPS-сертификат Let's Encrypt для IP продлевается автоматически;
- резервные копии не входят в MVP и будут рассматриваться отдельно после него.

В чистую production-базу загружаются пользователи, четверти 2026/27 и
справочники из `prisma/seed.ts`. До 1 сентября 2026 года дополнительно
загружается тестовая четверть командой `npm run db:study-demo`, чтобы семья могла
проверять систему до начала учебного года. Она не удаляется до отдельного решения.

## Параметры виртуальной машины для ревью

- Ubuntu 24.04 LTS;
- 2 vCPU с гарантированной долей 20%;
- 3 ГБ RAM; если этого окажется мало, память можно увеличить без переноса данных;
- сетевой HDD 30 ГБ — для нагрузки одной семьи его достаточно и он удерживает стоимость ближе к согласованному бюджету;
- статический публичный IPv4;
- вход только по SSH-ключу;
- открыты порты 22, 80 и 443; PostgreSQL наружу не открыт.

## Порядок первого запуска

1. Установить Docker, Nginx и Certbot 5.4+.
2. Скопировать проект в `/opt/family-motivation`.
3. Создать `.env.production` по примеру и заполнить настоящие PIN и секреты.
4. Запустить миграции и приложение:

   ```sh
   docker compose --env-file .env.production -f compose.production.yaml up -d --build
   ```

5. Один раз загрузить стартовые данные:

   ```sh
   docker compose --env-file .env.production -f compose.production.yaml run --rm migrate npx prisma db seed
   ```

6. Сначала включить `nginx-bootstrap.conf`, затем выпустить короткий IP-сертификат
   (в команде заменить `STATIC_IP`):

   ```sh
   sudo certbot certonly --webroot --webroot-path /var/www/certbot \
     --preferred-profile shortlived --ip-address STATIC_IP
   ```

   После этого заменить `STATIC_IP` в `nginx-https.conf.template`, включить
   полученную конфигурацию и перечитать Nginx.
7. Проверить системный таймер Certbot. Он запускает продление автоматически.
   В `/etc/letsencrypt/renewal-hooks/deploy/reload-nginx` добавить исполняемый
   файл с командой `systemctl reload nginx`, чтобы сервер подхватывал новый
   сертификат после каждого продления.

Создание платных ресурсов и первый запуск выполняются только после отдельного
подтверждения параметров выше.

Скрипт `bootstrap-server.sh` устанавливает эти программы на чистую Ubuntu и
добавляет 2 ГБ swap для первой сборки. `create-production-env.sh` создаёт
случайные серверные секреты и закрытый `.env.production`; PIN передаются ему
только во время запуска и не записываются в Git.
