# Семейная система мотивации — MVP

Мобильное семейное приложение для учёбы, самостоятельности, обменных баллов и наград. MVP реализован поэтапно и готовится к семейному пилоту.

## Что за что отвечает

- `src/app` — страницы и оформление Next.js;
- `src/lib/domain` — правила приложения, не зависящие от экрана и базы;
- `prisma/schema.prisma` — понятное описание таблиц PostgreSQL;
- `prisma/migrations` — последовательные изменения базы в обычном SQL;
- `prisma/seed.ts` — начальные данные для разработки;
- файлы `*.test.ts` — быстрые проверки правил через Vitest.

В стартовых данных есть Саша, Папа, Дедушка, четыре четверти 2026/2027 и одиннадцать школьных предметов. Папа добавляет и исправляет оценки 2–5 прямо в карточке предмета, без ввода даты. Среднее считается из оценок текущей четверти. Удаление можно отменить; предметы через интерфейс не добавляются. До 1 сентября 2026 года в production намеренно добавлена отдельная тестовая четверть для семейной проверки системы.

## Импорт отметок из дневника

`scripts/extract-study-sheet.py input.xlsx output.json` извлекает лист «Отметки» (требуется Python с openpyxl). `npx tsx scripts/import-study.ts output.json` показывает предварительный результат для базы из `DATABASE_URL`; `--apply` сохраняет его. Личные выгрузки не добавляются в Git.

Импорт обновляет только предметы и даты из файла, сохраняет остальные отметки четверти и пересчитывает арифметические средние. Повторная загрузка не удваивает отметки. Посещаемость и замечания не участвуют в среднем; неизвестные обозначения и предметы останавливают импорт. Ручные отметки без даты сохраняются при импорте. Изменение оценок обновляет рекомендацию, но действующее время изменяется только по кнопке «Применить сейчас».

## Реализовано в MVP

- персональный вход по PIN и роли ребёнка, администратора и взрослого;
- ежедневные отметки с подтверждением взрослого;
- домашние дела, новый продукт и журнал баллов;
- каталог и выдача наград;
- оценки текущей четверти и применение времени без недельных циклов;
- просмотр просроченных дней и компенсирующие исправления;
- PWA, production-контейнеры и подготовка к Yandex Cloud.

## Основные команды

- `npm run dev` — запустить приложение для разработки;
- `npm run test` — проверить правила;
- `npm run test:integration` — проверить транзакции и конкурентные сценарии в одноразовой изолированной PostgreSQL;
- `npm run test:e2e` — пройти ключевой сценарий ребёнка и взрослых в Chromium на одноразовой базе;
- `npm run build` — проверить производственную сборку;
- `npm run db:migrate` — применить изменения структуры базы;
- `npm run db:seed` — записать начальные данные.

Инструкция по размещению находится в [`deploy/README.md`](deploy/README.md). Секреты и настоящие PIN никогда не добавляются в Git.

## Безопасность тестов с базой

Интеграционные и браузерные проверки не используют `DATABASE_URL` разработчика. Скрипт создаёт временный кластер PostgreSQL на случайном порту (никогда не `5432`), применяет миграции к новой базе `family_motivation_integration` и удаляет весь временный каталог после завершения — в том числе при падении теста. Для запуска нужен локальный PostgreSQL 17 (`initdb`, `pg_ctl`, `createdb`). Браузерная проверка также требует установленный Chromium Playwright (`npx playwright install chromium`).

Контролируемые PIN тестового seed: `5555` — ребёнок, `0000` — администратор, `1111` — взрослый. Эти значения предназначены только для локального изолированного стенда.

## Журнал и экранное время — 28 сентября 2026

Время в день: 60 минут + 10 за каждый бонусный предмет со средним строго выше 4,50 − 15 за каждый жёлтый − 30 за каждый красный. Бонусные предметы: математика, русский язык, английский язык, география, история, биология, литература. Вычеты считаются по всем предметам с оценками. При трёх и более красных — 0 минут независимо от бонусов; иначе минимум 15 минут. Потолка 120 минут нет: семь бонусов без вычетов дают 130. Пороги: красный <3,40, жёлтый от 3,40 до 3,70 (не включая 3,70). Расчёт не округляет среднее перед сравнением. Предметы без оценок пропускаются. Цвета времени: красный → оранжевый → жёлтый → зелёный → голубой → синий → фиолетовый.

Миграция `20260928120000_manual_study_journal` переносит последний действующий лимит в `ScreenTimeState`, сохраняет прежние оценки и недельные решения. Новые ручные оценки не имеют даты, удаление мягкое (`deletedAt`). Старые недельные функции оставлены для совместимости с прежними тестами и инструментами, но интерфейс их не вызывает. При отсутствии четверти/оценок действующий лимит сохраняется. Новые ограничения наград и 15 минут за отдельное задание не добавлены.

UX-правки от 29 сентября: единые отступы карточек, добавление оценки в шапке предмета, выделение редактируемой записи и сообщение о сохранении в том же предмете. Компактное сравнение текущего и рекомендованного времени заменяет две большие карточки; шкала находится в раскрываемых правилах. После изменения оценок можно перейти к применению времени, но оно по-прежнему требует отдельного действия. Неактивные бонусы обозначены нейтрально. Данные и формула расчёта не менялись.
